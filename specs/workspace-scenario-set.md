# Workspace Fixture

## Summary

A workspace fixture is a directory under `fixtures/` that contains one reusable workspace state and one `fixture.yaml` file with one or more scenario definitions. Each scenario is executed by copying the workspace state into a fresh run directory, then invoking Codex inside that copy.

## Directory Layout

The canonical layout is:

```text
fixtures/
  README.md
  .env.skill
  go-sample-project/
    .env.skill
    fixture.yaml
    workspace/
      go.mod
      main.go
      README.md
```

`fixtures/README.md` is generated by `eval init` and explains local fixture authoring commands plus `suite.yaml` and `fixture.yaml`. `workspace/` contains the initial project state. `fixture.yaml` contains scenario definitions that reuse that initial state. The fixture directory name is both the fixture ID and title. `fixtures/.env.skill` provides common fixture environment variables, and `fixtures/<fixture-id>/.env.skill` provides fixture-specific overrides.

## Required Behavior

- The runner must discover fixtures under the suite config's fixture root, defaulting to `fixtures/<fixture-id>/`.
- Each scenario run must copy `fixtures/<fixture-id>/workspace/` into an isolated run workspace.
- The source `workspace/` directory must never be mutated by a run.
- Multiple scenarios in the same set must be independent even when they start from identical files.
- Reports must group results by fixture, scenario, model, variant, and attempt.

## Fixture File

`fixture.yaml` defines:

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `cases` | array | yes | Scenario definitions using [Test Case Model](test-case-model.md). |

## Example Fixture

```yaml
# fixtures/go-sample-project/fixture.yaml
cases:
  - title: Add CLI flag behavior
    prompt: |
      Add a --name flag to the sample Go CLI and update tests.
    expected:
      - expected: file contains
        path: main.go
        regex: "flag\\.String"
      - expected: file contains
        path: main_test.go
        text: "--name"

  - title: Analyze package structure
    prompt: |
      Analyze this Go project and summarize package responsibilities.
    expected:
      - expected: reply
        text: "package"
      - expected: file_not_exists
        path: main.go.bak
```

## Rules / Constraints

- A scenario ID must be unique within its fixture.
- The global run identity combines fixture ID and scenario ID.
- Scenario files must not use paths that escape the copied run workspace.
- Fixtures may contain helper files outside `workspace/`, but only files declared as artifacts or case inputs should be copied into runs.
- Optional `.env.skill` files may exist at the fixture root and fixture directory levels. They are read by the runner as environment inputs and are not part of the copied workspace unless explicitly placed under `workspace/`.
- Snapshot creation through `eval add-fixture` must exclude `fixtures/` and project-local `.agent/skills/` or `.agents/skills/` directories when the target path is the suite root.
- Snapshot creation through `eval add-fixture <name> <target-path> <prompt>` must add a case with `prompt: <prompt>` to `fixtures/<name>/fixture.yaml`.

## Native-Language Summary

`fixtures/<fixture>/workspace/` に共通の初期状態を置き、`fixture.yaml` の `cases` 配列に複数の挙動テストを書く。fixtureディレクトリ名がid/titleになる。同じ状態をケースごとに複製してCodexを実行し、結果をfixture単位で集計する。
